# 1. CENTRAL RESEARCH QUESTION

Answer:

> How reliably do frontier LLMs solve and validate actuarial tasks under a controlled, reproducible benchmark, and where do their failure modes differ?

Secondary questions:

1. Which model has highest actuarial numerical accuracy?
2. Which model produces most correct executable actuarial code?
3. Which model best detects invalid assumptions and deliberately planted actuarial errors?
4. Which model hallucinates least when information is insufficient?
5. Which model is most consistent across repeated runs?
6. Which model gives best accuracy/cost tradeoff?
7. Which model gives best accuracy/latency tradeoff?
8. Are observed differences statistically meaningful or likely noise?
9. Which actuarial domains favor different models?
10. Does model confidence correspond to actual correctness?

Never conclude simply:

> Model A is better than Model B.

Use:

> Model A significantly outperformed Model B on metric X under this benchmark and protocol.

If evidence insufficient, declare tie / inconclusive.

# 5. GENERATED TASKS TO REDUCE TRAINING CONTAMINATION

Do not primarily copy textbook/web benchmark questions.

Implement deterministic task generators using fixed random seeds.

Example:

```python
rng = np.random.default_rng(seed)
lambda_ = rng.uniform(...)
shape = rng.uniform(...)
scale = rng.uniform(...)
```

Generator produces:

1. task prompt
2. exact parameters
3. exact reference answer
4. tolerance
5. metadata
6. scoring function

Reference solutions must be produced independently from LLM outputs.

For analytic tasks, compute using trusted formulas / deterministic Python.

For simulation tasks, ground truth should preferably use analytic quantity when available.

If simulation itself is target, use large reference simulation with fixed seed and justified statistical tolerance.

# 6. TASK TYPES

Implement at least 4 objectively gradable task families.

## Type 1 — Numerical

Model returns structured final numerical answer.

Compare with ground truth using absolute/relative tolerance.

Example:

```python
np.isclose(
    model_value,
    expected_value,
    rtol=...,
    atol=...
)
```

Do not use arbitrary tolerance. Define mathematically justified tolerance per task.

## Type 2 — Multiple component calculation

Task may require several values.

Score each component independently.

Example:

```text
expected frequency
expected severity
pure premium
variance
```

This prevents one partially correct answer receiving full credit.

## Type 3 — Coding

Model must output Python function/code.

Execute in isolated test process.

Use:

* pytest
* hidden unit tests
* edge cases
* numerical tolerance
* optional property-based tests if dependency justified
* timeout
* no network
* controlled imports

Separate:

```text
code executes
tests passed
actuarial result correct
```

## Type 4 — Validation / diagnosis

Plant explicit defects in synthetic actuarial analysis.

Ground truth = defect IDs.

Measure:

* true positives
* false positives
* false negatives
* precision
* recall
* F1
* critical-defect recall

Avoid subjective free-form scoring as much as possible.

# 12. STATISTICAL COMPARISON

This section must be rigorous.

Because all models answer same tasks, comparisons are paired.

Compute:

* bootstrap 95% confidence intervals
* paired model differences
* effect sizes
* McNemar test for paired binary outcomes where appropriate
* paired permutation/bootstrap tests for continuous scores where appropriate

Multiple pairwise model comparisons create multiple-testing problem.

Apply correction such as:

```text
Holm-Bonferroni
```

Do not declare winner from tiny score differences.

Winner rule:

Model A may be called better than B on metric X only if:

1. point estimate favors A
2. uncertainty interval supports meaningful difference
3. paired statistical test supports difference after correction
4. effect size is non-trivial

Otherwise:

```text
No statistically supported difference / tie.
```

Overall ranking should distinguish:

```text
statistically supported ranking
descriptive ranking
```

Never hide uncertainty.
